`@suku/crypto` is a small set of security helpers built on the Web Crypto API. It has no
dependencies, runs on Node, Bun and edge runtimes, and works with or without the rest of Suku.

```bash
bun add @suku/crypto
```

<Callout type="warn">
  This package has not had an independent security audit. It uses only the platform's own
  primitives and conservative defaults, and it is covered by tests for the common attacks.
</Callout>

## JSON Web Tokens

Create one signer and verifier, bound to an algorithm and a key.

```ts title="auth/jwt.ts"
import { createJwt } from '@suku/crypto';
import { service } from '@suku/core';

export const Tokens = service('tokens', {
  services: { env: Env },
  create: ({ env }) =>
    createJwt<{ role: 'user' | 'admin' }>({
      secret: env.JWT_SECRET,
      issuer: 'my-api',
      expiresIn: '15m',
    }),
});
```

```ts
const token = await tokens.sign({ role: 'admin' }, { subject: user.id });
const payload = await tokens.verify(token);   // { role, sub, iss, iat, exp }
```

`verify` returns the payload or throws a `JwtError`. Treat any failure as "no token".

### Protecting routes

```ts title="auth/authenticate.ts"
import { Inject, type Middleware, type Next, RequestContext, Service, type ServiceOf, UnauthorizedException } from '@suku/core';
import { bearerToken } from '@suku/crypto';

@Service()
export class Authenticate implements Middleware {
  constructor(@Inject(Tokens) private readonly tokens: ServiceOf<typeof Tokens>) {}

  async use(ctx: RequestContext, next: Next) {
    const token = bearerToken(ctx.headers.get('authorization'));
    if (!token) throw new UnauthorizedException();
    try {
      ctx.set('user', await this.tokens.verify(token));
    } catch {
      throw new UnauthorizedException();
    }
    return next();
  }
}
```

```ts
route.get('/me', {
  middlewares: [Authenticate],
  handle: ({ ctx }) => ctx.get('user'),
});
```

### What verification checks

| Check | Failure code |
| --- | --- |
| Three well-formed parts, within the size limit | `malformed` |
| The header's algorithm equals the configured one | `algorithm_mismatch` |
| The signature | `invalid_signature` |
| `exp` is present and in the future | `invalid_claim`, `expired` |
| `nbf` has passed, `iat` is not in the future | `not_active`, `invalid_claim` |
| `issuer` and `audience`, when configured | `invalid_claim` |
| Your `schema`, when given | `invalid_claim` |

The algorithm is never taken from the token. That is what stops `alg: none` tokens and the
attack where an RSA public key is used as an HMAC secret.

### Options

| Option | Meaning |
| --- | --- |
| `algorithm` | Default `HS256`. Also HS384/512, RS, PS and ES at 256/384/512, and `EdDSA`. |
| `secret` | For HS algorithms. At least 32 bytes for HS256; shorter secrets are refused. |
| `privateKey`, `publicKey` | For the others. PEM (PKCS#8 and SPKI), JWK or `CryptoKey`. |
| `expiresIn` | Default `1h`. `false` issues tokens that never expire. |
| `issuer`, `audience` | Written when signing, required when verifying. |
| `clockTolerance` | Seconds of clock skew to allow. Default 0. |
| `schema` | A Standard Schema that validates and types the payload. |
| `previousSecrets`, `previousPublicKeys` | Old keys still accepted for verifying. |

A service that only verifies needs just the public key.

```ts
const verifier = createJwt({ algorithm: 'ES256', publicKey: env.JWT_PUBLIC_KEY, issuer: 'auth' });
```

Generate a secret once and keep it in your environment.

```ts
import { randomToken } from '@suku/crypto';
console.log(randomToken(32));
```

<Callout title="Tokens cannot be revoked">
  A signed token is valid until it expires. Keep access tokens short-lived, and keep refresh
  tokens in your database where you can delete them.
</Callout>

## Passwords

```ts
import { hashPassword, needsRehash, verifyPassword } from '@suku/crypto';

const stored = await hashPassword(input.password);      // save this string

if (!(await verifyPassword(input.password, user.passwordHash))) throw new UnauthorizedException();
if (needsRehash(user.passwordHash)) await users.setHash(user.id, await hashPassword(input.password));
```

Hashes use PBKDF2-HMAC-SHA256 with a random salt and 600,000 iterations, and carry their
parameters, so you can raise the work factor later and upgrade users as they log in.
PBKDF2 is the password function every Web Crypto runtime provides; if a native dependency is
acceptable, Argon2id is the stronger choice.

## Signed values

A signer makes a value tamper-proof while leaving it readable. Use it for cookies, webhook
payloads and links.

```ts
import { createSigner } from '@suku/crypto';

const signer = createSigner(env.COOKIE_SECRET);

const cookie = await signer.pack('user.42');        // "user.42.<signature>"
const value = await signer.unpack(cookie);          // "user.42", or undefined if altered

const ok = await signer.verify(rawBody, request.headers.get('x-signature') ?? '');
```

## Encrypted values

A sealer also hides the value. Use it for encrypted cookies, OAuth `state` and reset links.

```ts
import { createSealer } from '@suku/crypto';

const reset = createSealer(env.APP_SECRET, { purpose: 'password-reset' });

const link = await reset.seal({ userId: user.id }, { ttl: '30m' });
const data = await reset.unseal<{ userId: string }>(link);   // undefined if expired or altered
```

`purpose` binds a value to one use: something sealed for `password-reset` cannot be opened as
a session. Encryption is AES-256-GCM with a fresh nonce for every value.

## Random values and hashing

```ts
import { randomInt, randomToken, randomUUID, sha256, timingSafeEqual } from '@suku/crypto';

randomToken();            // 43 URL-safe characters, 256 bits: session ids, API keys
randomUUID();
randomInt(100000, 1000000);   // a 6-digit code, without modulo bias

await sha256(fileBytes);      // hex fingerprint. Not for passwords.
timingSafeEqual(providedKey, expectedKey);   // compare secrets without leaking timing
```

## Rotating a secret

Every helper accepts previous secrets. They are used to verify or decrypt, never to sign.

```ts
createJwt({ secret: env.JWT_SECRET, previousSecrets: [env.JWT_SECRET_OLD] });
createSigner(env.COOKIE_SECRET, { previousSecrets: [env.COOKIE_SECRET_OLD] });
```

Deploy with both, wait for old tokens to expire, then remove the old one.

## Not included

Encrypted JWTs (JWE), fetching JWKS from an identity provider, OAuth flows and token
revocation are outside this package.
