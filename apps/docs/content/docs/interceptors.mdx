---
title: Interceptors
description: Wrap the handler call to transform results or measure it.
icon: Repeat
---

An interceptor runs around the handler. `next()` resolves to the handler's **return value**,
before it becomes a `Response`, so reshaping results is direct. There is no RxJS.

```ts
import type { Interceptor, Next } from '@suku/core';

export class EnvelopeInterceptor implements Interceptor {
  async intercept(_ctx: RequestContext, next: Next<unknown>) {
    return { data: await next() };
  }
}
```

```ts
@Controller('users')
@UseInterceptors(EnvelopeInterceptor)
export class UsersController {
  @Get(':id')
  get() {
    return { id: '1' };          // client receives {"data":{"id":"1"}}
  }
}
```

## Timing and logging

```ts
const timing: InterceptorFn = async (ctx, next) => {
  const started = performance.now();
  try {
    return await next();
  } finally {
    console.log(ctx.route?.path, `${(performance.now() - started).toFixed(1)} ms`);
  }
};
```

## Handling errors

Errors thrown by the handler pass through `next()`, so an interceptor may catch and replace
them.

```ts
const fallback: InterceptorFn = async (_ctx, next) => {
  try {
    return await next();
  } catch (error) {
    if (error instanceof UpstreamTimeout) return { stale: true, items: [] };
    throw error;
  }
};
```

## Returning a Response

Return a `Response` to bypass serialisation, for a cache hit for example.

```ts
const cache: InterceptorFn = async (ctx, next) => {
  const hit = store.get(ctx.request.url);
  if (hit) return new Response(hit, { headers: { 'x-cache': 'hit' } });
  return next();
};
```

Interceptors nest: the first global one is outermost, the method-level one is closest to the
handler.
