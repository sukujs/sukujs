A route is created with `route.get`, `route.post`, `route.put`, `route.patch`,
`route.delete`, `route.head`, `route.options` or `route.all`. It takes a path and an options
object whose `handle` function produces the response.

```ts
import { route } from '@sukujs/core';
import { z } from 'zod';

const findUser = route.get('/users/:id', {
  params: z.object({ id: z.coerce.number() }),
  handle: ({ params }) => ({ id: params.id }),
});
```

The schemas are the single source of truth. They validate the request at runtime and type the
handler at compile time.

## Two ways to write them

Both styles create the same kind of route, and can be mixed freely.

<Tabs items={['In a class', 'Without a class']}>
  <Tab value="In a class">
    Services arrive through the constructor, and handlers use `this`.

    ```ts
    @Routes('/users')
    export class UsersRoutes {
      constructor(private readonly users: UsersService) {}

      findOne = route.get('/:id', {
        params: z.object({ id: z.coerce.number() }),
        handle: ({ params }) => this.users.find(params.id),
      });

      create = route.post('/', {
        body: CreateUser,
        handle: ({ body }) => this.users.create(body),
      });
    }
    ```

    Best when a resource has several routes that share dependencies.
  </Tab>
  <Tab value="Without a class">
    The route declares the services it needs, and they arrive in the handler by name.

    ```ts
    export const findOne = route.get('/users/:id', {
      params: z.object({ id: z.coerce.number() }),
      services: { users: UsersService },
      handle: ({ params, users }) => users.find(params.id),
    });
    ```

    Best for small services and one-off routes. It needs no decorators, so on Node it runs
    without a compile step.
  </Tab>
</Tabs>

Register either kind in a [feature](/docs/features), or directly on the app.

```ts
feature('users', { routes: [UsersRoutes, findOne] });
```

A missing entry in `services` is caught at startup, with the route and service named.

## What the handler receives

One object. Each part is typed by its schema, or is the raw value when there is none.

| Field | With a schema | Without |
| --- | --- | --- |
| `params` | The schema's output. | Strings, keyed by the names in the path. |
| `query` | The schema's output. | An object of strings. Repeated keys become arrays. |
| `body` | The schema's output. | `undefined`. Call `ctx.body()` to read it yourself. |
| `headers` | The schema's output. | The `Headers` object. |
| `ctx` | The [request context](/docs/request-context). | |
| `request` | The Fetch `Request`. | |
| services | One field per entry in `services`. | |

[Handlers](/docs/handlers) shows how to read each part and how to set status, headers and
cookies.

## Options

| Option | Purpose |
| --- | --- |
| `params`, `query`, `body`, `headers` | Schemas for the request. See [validation](/docs/validation). |
| `response` | Schema for the returned value. Validates it and strips undeclared fields. |
| `services` | Services to resolve from the request scope, by name. |
| `middlewares` | [Middlewares](/docs/middlewares) for this route only. |
| `onError` | [Error handler](/docs/errors) for this route only. |
| `status` | Success status. Default `200`, or `201` for `POST`. |
| `name` | Identity in logs and the route table. |
| `meta` | Free-form data for middlewares, read as `ctx.route.meta`. See [Meta](#meta). |
| `handle` | The handler. May be `async`. |

## Paths

| Pattern | Matches |
| --- | --- |
| `/users/me` | That exact path. |
| `/users/:id` | One segment, available as `id`. |
| `/files/*path` | The rest of the path, including nothing. |

Static segments win over parameters, and parameters over wildcards. Trailing slashes are
ignored, and `HEAD` falls back to the `GET` route. A known path with the wrong method gets
`405` with an `Allow` header.

### Checked against the schema

The path is read at compile time. A `params` schema must cover every parameter in it.

```ts
route.get('/users/:id', {
  params: z.object({ userId: z.string() }),   // compile error: `id` is missing
  handle: () => {},
});

route.get('/users/:id', {
  handle: ({ params }) => params.idd,          // compile error: no `idd` in the path
});
```

## Return values

| Returned | Response |
| --- | --- |
| An object or array | JSON. |
| A string | `text/plain`. |
| `undefined` or `null` | `204 No Content`. |
| `Uint8Array` or `ArrayBuffer` | `application/octet-stream`. |
| `ReadableStream`, `Blob`, `FormData` | Passed to `Response` as the body. |
| A `Response` | Sent as it is. |

```ts
import { redirect } from '@sukujs/core';

route.get('/old', { handle: () => redirect('/new', 301) });
route.post('/jobs', { status: 202, handle: ({ ctx }) => queue.add(ctx) });
```

## Route names

A class field's name, or a group's key, becomes the route's name. It does not affect the URL.
It identifies the route in the route table, in logs, and in anything generated from your
routes.

```ts
app.routes;
// [{ method: 'GET', path: '/users/:id', name: 'UsersRoutes.findOne' }, ...]
```

`ROUTE_TABLE` holds the same list with each route's feature and options (its schemas, status
and `meta`). Read it with `app.get(ROUTE_TABLE)`, or inject it. [`@sukujs/openapi`](/docs/openapi)
is built on it.

## Meta

`meta` is free-form data attached to a route. The route does nothing with it. A
[middleware](/docs/middlewares) reads it as `ctx.route.meta` and decides what to do, so one
middleware can treat each route differently without knowing any of them.

```ts
route.delete('/reports/:id', {
  meta: { roles: ['admin'], audit: 'report.delete' },
  handle,
});
```

`ctx.route` is `undefined` when no route matched the request, so read it as `ctx.route?.meta`.

### Give it a type

`meta` accepts any object. Declare what your app puts in it once, with a function that checks
it where a route is declared and one that reads it back.

```ts title="meta.ts"
import type { RequestContext } from '@sukujs/core';

// A `type`, not an `interface`: only a type alias fits the route's `meta` option.
export type AppMeta = {
  /** No token needed. */
  public?: boolean;
  /** Only these roles may call the route. */
  roles?: string[];
  /** Seconds a successful response may be cached. */
  cache?: number;
  /** Written to the audit log when the route succeeds. */
  audit?: string;
};

/** Checks the keys where a route is declared. */
export const meta = (value: AppMeta) => value;

/** Reads them back, typed. Empty when no route matched. */
export const metaOf = (ctx: RequestContext) => (ctx.route?.meta ?? {}) as AppMeta;
```

```ts
route.get('/health', { meta: meta({ public: true }), handle });
route.get('/health', { meta: meta({ pubic: true }), handle }); // error: unknown key
```

The examples below use these two functions.

### Open a route under an app-wide check

Authentication usually runs for every request, with a few routes left open. Mark those
routes instead of listing their paths in the middleware.

```ts
const authenticate = middleware(async (ctx, next) => {
  // No route matched: let the 404 through. A public route needs no token.
  if (!ctx.route || metaOf(ctx).public) return next();
  const user = await verify(ctx.headers.get('authorization'));
  if (!user) throw new UnauthorizedException('Sign in first');
  ctx.set('user', user);
  return next();
});

route.get('/health', { meta: meta({ public: true }), handle });
route.get('/me', { handle: ({ ctx }) => ctx.get<User>('user') }); // needs a token
```

### Restrict a route to some roles

```ts
const requireRoles = allow((ctx) => {
  const roles = metaOf(ctx).roles ?? [];
  return roles.length === 0 || roles.includes(ctx.get<User>('user')?.role ?? '');
});

route.delete('/reports/:id', { meta: meta({ roles: ['admin'] }), handle });
```

A route without `roles` is open to every signed-in user. A wrong role gets a `403`.

### Configure a shared middleware per route

One middleware, a different setting on each route. Here, how long a response may be cached.

```ts
const cacheControl = middleware(async (ctx, next) => {
  const response = await next();
  const seconds = metaOf(ctx).cache;
  if (seconds && response.ok) ctx.setHeader('cache-control', `public, max-age=${seconds}`);
  return response;
});

route.get('/prices', { meta: meta({ public: true, cache: 60 }), handle });
```

The same shape works for a rate limit, a request timeout, a feature flag or a body size.

### Record what happened

A label on the route, written to the log once the route has succeeded.

```ts
const audit = middleware(async (ctx, next) => {
  const response = await next();
  const action = metaOf(ctx).audit;
  if (action && response.ok) {
    ctx.provider.get(Logger).info('audit', { action, user: ctx.get<User>('user')?.name });
  }
  return response;
});

route.delete('/reports/:id', {
  meta: meta({ roles: ['admin'], audit: 'report.delete' }),
  handle,
});
```

Register the four once, in this order, and every route is covered:

```ts
Suku.create({
  middlewares: [authenticate, requireRoles, cacheControl, audit],
  features: [AppFeature],
});
```

### Check every route at startup

[`ROUTE_TABLE`](#route-names) lists every route with its meta. Use it to catch a route that
someone forgot to protect, before the app takes requests.

```ts title="main.ts"
const unguarded = app
  .get(ROUTE_TABLE)
  .filter(({ config }) => {
    const rules = (config.meta ?? {}) as AppMeta;
    return !rules.public && !rules.roles;
  })
  .map((r) => `${r.method} ${r.path}`);

if (unguarded.length > 0) {
  throw new Error(`Routes with no access rule: ${unguarded.join(', ')}`);
}
```

[`@sukujs/openapi`](/docs/openapi#route-meta) reads meta the same way to build its document.

## Groups

`route.group` shares a prefix, middlewares and an error handler without a class.

```ts
export const admin = route.group('/admin', { middlewares: [requireAdmin] }, {
  stats: route.get('/stats', { handle: () => getStats() }),
  purge: route.post('/purge', { handle: () => purge() }),
});
```

## Classes in detail

`@Routes(prefix, options)` accepts `middlewares`, `onError` and `lifetime`.

A routes class is a singleton by default. Fields that are not routes are ignored, and a class
with no route fields is rejected at startup.

Constructor-injecting a scoped service promotes the class to scoped automatically (Nest-like).
To keep the class a singleton, take request-bound services on the route instead:

```ts
@Routes('/orders')
export class OrdersRoutes {
  constructor(private readonly catalog: Catalog) {}

  place = route.post('/', {
    body: PlaceOrder,
    services: { uow: UnitOfWork },          // scoped: one per request
    handle: ({ body, uow }) => uow.orders.place(body, this.catalog),
  });
}
```

Or declare it explicitly with `@Routes('/orders', { lifetime: 'scoped' })`.

<Callout title="Scoped classes and startup">
  At startup Suku builds a throwaway instance with empty constructor arguments only to read
  route fields — injected services are **not** created then. The real instance (and its
  scoped dependencies) is constructed per request. Do not touch constructor parameters in
  the constructor body or in field initializers.
</Callout>
